Three sizes

Small = plain CRUD, 7 routes. Mid = add auth, roles, logging, error codes, paging, state machine. 16 routes. Large = add module split, ETag concurrency, idempotency keys, soft delete, audit log, outbox, quota, bulk write, search, reports, metrics. 34 routes.

Spec written first. Test written second. Code written last. Nothing counts until server run and pass every test over real HTTP.

Low-level penalty is fixed cost, not multiplier.

C and C++ and Zig write HTTP parser, JSON parser, JSON writer, socket loop — one time. Python and C# import all that. So Python start way ahead, then gain nothing more. Every language pay same for route number 35.

Worst-to-best gap: 4.01× at 7 routes → 3.18× at 16 → 2.71× at 34.

So: measure on toy app, you punish C too hard. Old rule "C cost about 1.9×" is near right on big app, very wrong on small app.

Big findings

PHP only one get slower

PHP make new process every request. Cannot hold memory. So rewrite whole store file every request. Big app grow audit log, file hit 512 KB, PHP re-parse it every time. p50 go 17.96 ms → 30.07 ms. Everyone else flat or better.

Java JIT worth 2.3×

Java get faster while run: p50 1.452 → 0.638 ms. Only big improver. But pay 5,041 ms cold start and 199.6 MB RAM. Fine for long server. Bad for scale-to-zero.

C and C++ fast per request, slow per connection

Both send Connection: close. New TCP handshake every request. p50 fine at 0.7 ms, but only 181 and 213 req/s versus Zig 2,684.

Zig win all speed number

Best p50, best req/s, least CPU, least RAM at 3.3 MB. Standard library only, zero dependency. Cost 1.84× Python token, and Zig 0.16 delete std.net so almost no example exist.

C# dense, not bloated

C# beat Python on line count at small and mid — 134 vs 138, 451 vs 472. Modern C# not the old enterprise boilerplate.

Runtime spread beat token spread

Token spread 2.71×. Speed spread 133×. RAM 60×. CPU 301×. Cold start 126×. Source size flattest thing measured here.

Know this before you quote number

  • Framework included. Real framework each language, not bare stdlib. So this measure ecosystem too, not pure syntax. FastAPI hide work C must write by hand.
  • Three things left out on purpose. No password hash, no signed token, no timestamp in body. Keep work identical across ten languages. All three cheap in Python, expensive in C — so leaving them out make C number kinder, not harsher.
  • Count read cost, not write cost. This count tokens to read working code. Not count retries a compiler would catch. That is where strong types pay back.
  • Tokenizer is proxy. tiktoken, not Claude tokenizer. Ratio hold across two encoders. Absolute number will move.
  • p99 lie on Windows. Tail land on 15.6 ms timer tick. p50 and p90 solid.
  • One machine, one run, one request at a time. No concurrency test — four builds single-thread by design, so concurrency test would rank thread model, not language.
  • Three sizes = three dots. Trend clear, curve shape not proven.
  • C hit own ceiling. C use fixed arrays. At 10,000 requests on big app, audit table full at 2,048 and 748 requests answer 409. Real limit, and it make C latency look slightly better than true.
