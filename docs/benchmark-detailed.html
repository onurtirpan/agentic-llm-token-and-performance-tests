1. Three sizes

Tierroutestests What it add
small722 CRUD, validation, derived field, two-key sort, aggregate with rounded mean and nullable field
mid1698 session auth, roles, row-level access, middleware chain, structured JSON log, error envelope with machine codes and request id, multi-error validation, paging, whitelisted sort, status state machine, cascade delete, conflicts
large34139 forced 4-module split, ETag + If-Match concurrency, idempotency keys with replay, soft delete and restore, audit trail, outbox, per-session quota, bulk write with per-item result, search, grouped reports, metrics by route pattern, comments, user admin, admin-only field

Large tier force module split: domain, store, service, api, each import only from above. That is real enterprise shape, and it is where language with no module pay twice — C and C++ must write header per module. C three header alone = 368 of its 3,245 line.

2. How we verify

Nothing count until it work. Two gate, both must pass.

Gate 1 — conformance

Real HTTP against live server on port 8080. No mock. Check status code, exact top-level key set, every value, list order, validation-detail order, and headers X-Request-Id, ETag, X-Quota-Remaining, Idempotency-Replayed. Float compare with 1e-9 tolerance, everything else exact.

Gate 2 — log check

Mid and large only. Tool read server stdout and check every log line: one JSON object per line, exact key order, level match status class, no query string in path, right type each field. Spec also say nothing but log go to stdout, so each build must silence own framework.

Order of work each tier: spec first, test second, then one Python reference driven to full pass, then other nine. Every build re-verified by hand, separate from report it come with. Result: 30/30 pass 22 / 98 / 139, and all 20 mid and large build pass log check.

3. Our two mistakes

Two languages look bad because of us, not because of them.

Both found by asking why a number look worse than it should. Both fixed before publish. Old data kept for audit.

Mistake 1 — PHP had OPcache off

php -S run CLI SAPI. opcache.enable_cli default Off. So PHP recompile all of Slim from source every request. No production PHP run that way. Fix near halve PHP p50 on mid tier, 10.43 → 6.29 ms.

Mistake 2 — C and C++ had no keep-alive

Both send Connection: close every response, so new TCP handshake per request. HTTP/1.1 default is persistent connection. Zig also hand-write raw socket with no framework, and Zig do keep-alive right — that is what prove this our defect, not property of C.

Small tier, 10,000 requestbefore afterchange
C p5011.587 ms 0.166 ms70× faster
C req/s96 3,45436× more
C++ p5011.164 ms 0.200 ms56× faster
C++ req/s99 2,56126× more

Before fix we ranked C 8th on speed. C actually near top. Fix also add safety: cap 1,000 request per connection, SO_RCVTIMEO 5 s so one idle client cannot deadlock single-thread accept loop, and TCP_NODELAY in C because it write header and body as two send and Nagle would stall second one.

Correct keep-alive cost token. C small tier go 3,954 → 4,981 token, about +26%. Protocol-correct code is more code. Every number on this page is the corrected one, so C and C++ look worse on token than before and much better on speed. That is the honest trade.

Everything else checked for same kind of handicap and found fair: all ten run single process, default framework setting, compiled language all use standard release mode (-O2, --release, ReleaseSafe), no language get tuning flag another is denied.

4. Where PHP time really go

After OPcache fix, we measure layer by layer. Same server, fresh store, GET only, warm. Answer surprise us.

Layerp50this layer add
bare PHP, no framework0.874 ms —
+ Slim construct, no store, no logic 5.113 ms+4.24 ms
+ our small-tier store and routes5.384 ms +0.27 ms
+ our large-tier store and routes6.410 ms +1.30 ms

Bare PHP 0.874 ms — faster than C# and faster than Python. About 94% of the gap is Slim container, router and middleware stack built from scratch on every request. That is what shared-nothing require. Every other language here build router one time at startup and keep it for life of process.

Our file store is not main cost at normal size. It become main cost only at large tier under sustained load, where audit trail and outbox grow and whole store re-serialize per request: p50 25.64 ms at 100 request, 15.87 at 1,000, 31.57 at 10,000. That come from spec forbidding database plus PHP unable to hold memory, and APCu not available on this box. Real PHP service keep audit in database and never pay it.

Honest summary: PHP number here measure the shared-nothing execution model, not the language. Persistent runtime — Swoole, RoadRunner, FrankenPHP — remove the per-request rebuild completely. Not tested here.

Pattern flip between fast and slow, and mechanism explain both half. Fast server: req/s unreliable. req/s come from the mean, and one 15.6 ms stall cost same wall clock as ~50 normal request, so stall count decide it — Go swing 2×. PHP: p50 unreliable, req/s steady. At ~12 ms per request a stall is worth about one request so mean stay smooth, but PHP cost is file I/O plus framework boot, both bimodal on page cache, so median jump.

What that mean: rank on p50. The req/s order among C, C++, Zig, Go and Rust is not established by this data — their p50 order is. And PHP p50 read as band, not point: published large figure 31.57 ms sit above the 11.4–15.4 ms band measured at 1,000 request, because the large store grow during a 10,000 request run. Direction real, exact value not reproducible.

Fix properly need repeat run with median, real load generator, tuned timer host. Bigger study than this. Pretending otherwise would be worse than saying so. Raw data in perf-variance/.

13. Findings

Abstraction cliff is step, not slope

At 7 routes C look terrible, 5.05×. At 34 routes it is 2.80×. Scaffolding written once then spread over every feature after. Most actionable result here: size a real backend from a toy comparison and you over-punish low-level by near double.

C use least CPU of all ten

0.059 CPU ms per request on big app. 313× less than PHP, 27× less than Java. Also fastest cold start, 47 ms. And it cost the most token of anything measured.

Zig use least RAM

3.3 MB idle, versus Java 191 MB — 58×. Standard library only, zero dependency, all three tiers. Cost: 1.84× Python token, and Zig 0.16 delete std.net so almost no example exist for it.

PHP only one degrade under load

Large tier p50 25.64 → 31.57 ms, drift 1.23×. Audit log grow, whole store re-serialize each request. And 18.5 CPU ms per request. Everyone else flat or better.

Java JIT worth 2.2×

p50 1.304 → 0.595 ms across the run, drift 0.46×, only big improver. Bill come at start: 5,275 ms cold start, 191 MB RAM. Deployment shape decide whether that matter at all.

Go overtake Rust on token at large

1.56× versus 1.66×, after losing at mid. Go overhead is per-declaration, and the forced 4-module split gave it somewhere to spread that. Go still write most line of any managed language, 2,338.

C# dense, not bloated

Beat Python on line count at small and mid — 134 vs 138, 451 vs 472. Then lose second place to TypeScript at large and become fastest-growing language, 11.07×. Module split tax static typing at every boundary.

Token track character, not line

Java write 550 mid line vs Rust 833 and still cost fewer token, because Rust line narrow. Go write fewer character than Java, 23,400 vs 23,652, yet cost 1,495 more token: Go encode 3.6 char per token vs Java 4.6.

Runtime spread crush token spread

Token 2.80×. Speed 145×. Throughput 85×. RAM 58×. CPU 313×. Cold start 112×. Source size is flattest axis in whole study.

14. Data quality

Every departure from clean run, said out loud instead of smoothed over.

  1. C return 748 conflict at large tier, 10,000 request. C use fixed array and MAX_AUDIT is 2,048. Cycle write three audit entry, so table fill after about 680 cycle and further write answer 409. Count was 8,781 200, 477 201, 748 409. So C latency there look slightly better than true, because rejected write is cheap. Also a real finding: C is only build with hard ceiling on accumulated state.
  2. p99 and max are host artifact. They cluster on multiple of 15.6 ms, the Windows timer tick, and jump up to fortyfold from p90. That is sequential client losing scheduling quantum. p50 and p90 stable.
  3. Cold start had 500 ms floor, now removed. First probe used HTTP client, and on Windows a refused loopback connection take hundreds of ms to report, which floored every cold start near 500 ms and made all fast binary look identical. Raw socket probe replace it, and harness now measure own detection cost every run.
  4. Peak RSS read 0.0 MB once. A fast build finish 100 request inside one 20 ms sampling interval after peak was zeroed. Peak now seeded from direct reading.
  5. CPU at 100 request unusable and not reported. Windows process CPU counter have about 15.6 ms resolution so short phase round to zero.
  6. Perf harness once hung instead of failing. Old readiness probe left its connection open, and Zig single-thread server kept serving that dead socket and never accepted the real client. Worse, a failed request record no sample, so the loop while samples < target spun forever. Probe now close, and the loop raise on an error ceiling or on any cycle producing zero sample.
  7. One machine, one run, sequential client. No repetition across reboot, no process pinning, no tuned timer resolution. Sound for relative comparison, not for absolute capacity.

15. Where the thirty builds differ

No test case reach any of these. Recorded because each move the token count a little, or because a language force the choice. Full list of sixteen in METHODOLOGY.md.

  • C# call the entity TaskItem, because Task collide with System.Threading.Tasks.Task. And every language use baseScore not base, because base is a C# keyword.
  • PHP write its store to a file. PHP start fresh process per request and cannot hold memory, and APCu not on this box. Only build that touch disk. Property of the execution model, not a shortcut.
  • C, C++ and Zig reject unknown JSON key with 400; other seven ignore it. C and C++ would need recursive value skipper; Zig inherit it from std.json default.
  • String length unit differ. Python, Rust, PHP, Go and Zig count character. Java and C# count UTF-16 unit. C and C++ count byte. Every test string ASCII so all agree.
  • Idempotency scope is unpinned. Spec say every POST accept the key; reference wire four route. Eight build follow reference, C follow the prose. No test case separate them — so this is a defect in our test, not in any build.
  • C use fixed capacity everywhere and return 409 on overflow. Real ceiling the other nine do not have.
  • Header timing force three different mechanism. FastAPI can set header after handler return. ASP.NET need Response.OnStarting, Spring need a ThreadLocal written during the handler, because both commit the response while writing the body. Spring also rewrite a bare ETag into a quoted one unless set on the raw servlet response.

16. Limits — read before you quote number

  1. Framework included, so this measure ecosystem too. Real framework each language, not bare stdlib. FastAPI and Minimal API hide an HTTP parser, JSON parser, JSON writer and socket loop that C, C++ and Zig write by hand. Real gap, real for a team, but not a measure of pure syntax. A stdlib-only run would squeeze the band hard and is not done here.
  2. Three thing left out on purpose. No password hash, no signed token, no wall-clock timestamp in body. Each keep the work identical across ten languages. Each is one library call in nine of them and a hundred-line detour in C — so leaving them out make the reported ratio kinder to C, not harsher.
  3. Count read cost, not write cost. This count token to express working code once. It do not count the retries a compiler would have caught, which is exactly where strong typing pay its token back.
  4. Tokenizer is proxy. tiktoken o200k_base and cl100k_base, neither is Claude tokenizer, and no offline Claude tokenizer available. Absolute count will move elsewhere; order hold across both encoder, which is why the ratio column is the one to quote.
  5. One workload shape. JSON over HTTP, CRUD, in-memory state. Say nothing about numeric work, streaming, heavy concurrency, or a real database.
  6. Author effect. Same author wrote or directed all thirty, so style is more consistent than thirty independent team would be — that likely reduce variance versus the real world. Other way, per-language idiom expertise is uneven, and a specialist might write any one of these tighter.
  7. Three size = three dot. The shrink is large and consistent, monotonic for six of ten and directionally right for eight, but three dot do not fix the shape of a curve.
  8. No concurrency test. C, C++, Zig and the PHP built-in server are single-thread by design, so a concurrent benchmark would rank thread model rather than language. Separate study.
